## 1. 产品概述

### 1.1 产品名称

**售后服务工单管理系统**（After-Sales Work Order Management System）

### 1.2 产品目标

| 编号 | 目标 | 衡量标准 |
|------|------|----------|
| G1 | 将售后工单从 Excel 迁移至 Web 系统，实现工单全生命周期数字化管理 | 工单录入、查询、汇总功能 100% 覆盖 Excel 原有能力 |
| G2 | 提供基于角色的权限控制与用户认证，保障数据安全 | 支持至少 3 种角色、细粒度模块级权限控制 |
| G3 | 支持 PC 端与移动端响应式适配，随时随地进行工单管理 | 核心页面在 375px~1920px 宽度范围内可用 |

### 1.3 核心价值

- **效率提升**：在线录入工单、自动计算金额、联动选择客户联系人，减少手工操作错误
- **数据洞察**：多维度汇总查询（按客户、按时间、按售后人员、按结款状态），实时掌握业务全貌
- **安全可控**：用户认证 + 角色权限管理，确保敏感数据仅授权人员可访问
- **灵活部署**：Docker 容器化部署，一键启动应用与数据库，降低运维成本

## 2. 用户角色定义

### 2.1 角色概览

| 角色 | 说明 | 权限范围 |
|------|------|----------|
| **管理员（Admin）** | 系统最高权限角色，默认账号 `admin` | 全部功能模块：工单管理、基础数据管理、汇总查询、用户管理、权限管理、系统配置 |

## 4. 用户故事

### 4.1 登录认证模块

> **US-01**：作为系统用户，我希望通过用户名和密码登录系统，以便安全地访问我的工作台。  
> **US-02**：作为管理员，我希望首次登录后系统提示我修改默认密码，以保障系统安全。  
> **US-03**：作为已登录用户，我希望可以随时登出系统，以防止他人使用我的会话。  

### 4.2 工单录入模块

> **US-04**：作为售后人员，我希望选择客户后系统能自动联动出该客户的联系人列表，以便快速选择正确的联系人。  
> **US-05**：作为售后人员，我希望选择联系人后自动带出联系电话，以减少重复输入。  
> **US-06**：作为售后人员，我希望输入人工费、材料费、交通差旅费后系统自动计算合计金额，以避免计算错误。  
> **US-07**：作为售后人员，我希望工单编号自动生成且递增，以避免编号冲突。  
> **US-08**：作为售后人员，我希望录入时间自动生成当前时间，以减少手动填写。  
> **US-09**：作为售后人员，我希望可以选择多个售后人员共同参与一个工单，以反映实际团队协作情况。  

### 4.3 工单管理模块

> **US-10**：作为售后主管，我希望在工单列表中看到未结款工整行标红显示，以便快速识别待结款工单。  
> **US-11**：作为管理员，我希望可以搜索和筛选工单列表（按客户、日期、结款状态），以便快速定位目标工单。  
> **US-12**：作为管理员，我希望可以删除错误录入的工单，以保持数据准确性。  

### 4.4 基础数据管理模块

> **US-13**：作为管理员，我希望可以新增/编辑/删除售后人员，以保持人员名单的最新状态。  
> **US-14**：作为管理员，我希望可以新增/编辑/删除客户信息，以适应业务变化。  
> **US-15**：作为管理员，我希望可以管理每个客户的多个联系人，以应对不同对接场景。  

### 4.5 汇总查询模块

> **US-16**：作为售后主管，我希望查看总体汇总数据（工单总数、各项费用合计、结款统计），以掌握整体业务概况。  
> **US-17**：作为售后主管，我希望按客户名称、日期范围、结款状态进行组合查询，以分析特定条件下的业务数据。  
> **US-18**：作为售后主管，我希望查看组合查询的明细列表和合计行，以了解具体工单详情。  
> **US-19**：作为售后主管，我希望按售后人员汇总工单数量和金额，以评估个人工作绩效。  
> **US-20**：作为财务人员，我希望查看未结款工单汇总，以跟进结款进度。  

### 4.6 权限管理模块

> **US-21**：作为管理员，我希望创建用户并分配角色，以控制不同人员的系统访问权限。  
> **US-22**：作为管理员，我希望可以启用或禁用用户账号，以管理离职人员的系统访问。  
> **US-23**：作为管理员，我希望可以自定义角色并配置模块级权限，以灵活适配组织架构。  

### 4.7 仪表盘模块

> **US-24**：作为管理员，我希望登录后看到关键指标仪表盘（工单总数、总金额、已结款/未结款金额），以快速了解业务状态。

## 5. 功能详细需求

### 5.1 登录认证模块

#### 5.1.1 登录

| 需求项 | 描述 |
|--------|------|
| 功能描述 | 用户通过用户名和密码登录系统 |
| 输入字段 | 用户名（必填）、密码（必填） |
| 验证规则 | 用户名不区分大小写；密码错误连续5次锁定账号30分钟 |
| 认证方式 | JWT Token，有效期 8 小时，支持刷新 |
| 成功行为 | 跳转至仪表盘页面 |
| 失败行为 | 提示"用户名或密码错误"，剩余尝试次数 |
| 响应式 | 登录页面居中卡片布局，PC/移动端通用 |

#### 5.1.2 登出

| 需求项 | 描述 |
|--------|------|
| 功能描述 | 清除当前会话，返回登录页 |
| 触发方式 | 点击顶部栏/侧边栏的"退出登录"按钮 |
| 行为 | 清除本地 Token，跳转登录页 |

#### 5.1.3 首次登录强制改密

| 需求项 | 描述 |
|--------|------|
| 功能描述 | 默认 admin 账号及新创建用户首次登录时强制修改密码 |
| 触发条件 | 用户标记 `must_change_password = true` |
| 行为 | 弹出修改密码对话框，完成修改后进入系统 |
| 密码规则 | 至少 8 位，包含字母和数字 |

### 5.3 工单录入模块

#### 5.3.1 工单字段定义

| 序号 | 字段名 | 类型 | 必填 | 默认值 | 说明 |
|------|--------|------|------|--------|------|
| 1 | 工单编号 | String | 是 | 自动生成 | 格式：4位递增数字（0001, 0002...） |
| 2 | 客户名称 | Select | 是 | — | 来源：基础数据-客户列表 |
| 3 | 录入时间 | DateTime | 是 | 当前时间 | 自动填充，不可编辑 |
| 4 | 联系人 | Select | 是 | — | 来源：基础数据-客户联系人表，与客户名称联动 |
| 5 | 联系电话 | String | 是 | 自动带出 | 选择联系人后自动填充 |
| 6 | 售后人员 | MultiSelect | 是 | — | 来源：基础数据-售后人员列表，支持多选 |
| 7 | 售后描述 | Textarea | 是 | — | 文本描述，最长 1000 字 |
| 8 | 人工费(元) | Number | 否 | 0 | 非负数，精度 2 位小数 |
| 9 | 材料费(元) | Number | 否 | 0 | 非负数，精度 2 位小数 |
| 10 | 交通差旅费(元) | Number | 否 | 0 | 非负数，精度 2 位小数 |
| 11 | 合计金额(元) | Number | — | 自动计算 | = 人工费 + 材料费 + 交通差旅费，只读 |
| 12 | 是否结款 | Boolean | 是 | 否 | 是/否，默认"否" |

#### 5.3.2 交互逻辑

1. **客户名称 → 联系人联动**：选择客户后，联系人下拉框仅显示该客户的联系人列表
2. **联系人 → 联系电话自动带出**：选择联系人后，联系电话字段自动填充对应号码
3. **金额自动计算**：人工费、材料费、交通差旅费任一变化时，合计金额实时更新
4. **工单编号自动生成**：系统查询当前最大编号 +1，格式化为 4 位数字

#### 5.3.3 表单校验

- 客户名称：必选
- 联系人：必选（且必须属于已选客户）
- 售后人员：至少选择 1 人
- 售后描述：必填，1~1000 字
- 费用字段：非负数，最大 999999.99

### 5.4 工单管理模块

- 可编辑字段：客户名称、联系人、联系电话、售后人员、售后描述、各项费用、是否结款

- 仅管理员可删除

#### 5.4.4 工单详情

- 展示工单完整信息（所有字段）
- 展示创建人、创建时间、最后修改人、最后修改时间
- 提供编辑、返回列表操作

### 5.6 汇总查询模块

#### 5.6.1 总体自动汇总

| 汇总项 | 计算逻辑 |
|--------|----------|
| 工单总数 | `COUNT(*)` 所有未删除工单 |
| 人工费合计 | `SUM(labor_cost)` |
| 材料费合计 | `SUM(material_cost)` |
| 交通差旅费合计 | `SUM(travel_cost)` |
| 工单总金额 | `SUM(total_amount)` |
| 已结款工单数 | `COUNT(*) WHERE is_paid = true` |
| 已结款金额 | `SUM(total_amount) WHERE is_paid = true` |
| 未结款工单数 | `COUNT(*) WHERE is_paid = false` |
| 未结款金额 | `SUM(total_amount) WHERE is_paid = false` |

**展示方式**：指标卡片网格布局（3×3），PC 端一行展示，移动端自适应换行。

#### 5.6.2 组合查询

**筛选条件**（均可选，留空=不限）：

| 条件 | 类型 | 说明 |
|------|------|------|
| 客户名称 | 下拉选择 | 来源：客户列表，支持多选 |
| 开始日期 | 日期选择 | 筛选录入时间 >= 开始日期 |
| 结束日期 | 日期选择 | 筛选录入时间 <= 结束日期 |
| 是否结款 | 下拉选择 | 全部/已结款/未结款 |

**查询汇总结果**：

| 汇总项 | 说明 |
|--------|------|
| 查询工单数 | 匹配条件的工单总数 |
| 人工费合计 | 匹配工单的人工费求和 |
| 材料费合计 | 匹配工单的材料费求和 |
| 交通差旅费合计 | 匹配工单的交通差旅费求和 |
| 工单总金额 | 匹配工单的合计金额求和 |
| 其中未结款金额 | 匹配工单中 `is_paid = false` 的合计金额求和 |

**查询明细列表**：

- 展示匹配工单的完整字段
- 最后一行为合计行（各项费用汇总）
- 最多展示 50 条记录（超出提示"仅展示前50条，共 N 条"）
- 支持导出（P2）

#### 5.6.3 各售后人员工单汇总

| 字段 | 计算逻辑 |
|------|----------|
| 售后人员 | 售后人员姓名 |
| 参与工单数 | 工单的 `after_sales_staff` 字段包含该人员姓名的工单计数 |
| 参与工单金额 | 上述匹配工单的合计金额求和 |
| 其中未结款金额 | 匹配工单中 `is_paid = false` 的合计金额求和 |

**匹配规则**：按字符串包含匹配（售后人员字段以"、"分隔，如"张伟、李娜"包含"张伟"和"李娜"）。

**展示方式**：表格列表，支持按工单数/金额排序。

### 7.5 数据库设计概要

#### 核心表结构

| 表名 | 说明 | 关键字段 |
|------|------|----------|
| `users` | 用户表 | id, username, password_hash, display_name, role_id, status, must_change_password, last_login_at |
| `roles` | 角色表 | id, name, description, permissions(JSON) |
| `after_sales_staff` | 售后人员表 | id, name, phone, status, created_at |
| `customers` | 客户表 | id, name, status, created_at |
| `customer_contacts` | 客户联系人表 | id, customer_id(FK), name, phone, status |
| `work_orders` | 工单表 | id, order_no, customer_id(FK), contact_id(FK), contact_phone, staff_names, description, labor_cost, material_cost, travel_cost, total_amount, is_paid, created_by(FK), created_at, updated_by(FK), updated_at, is_deleted |
| `operation_logs` | 操作日志表（P2） | id, user_id(FK), action, module, target_id, detail, created_at |

#### 表间关系

- `users` → `roles`：多对一（一个角色可对应多个用户）
- `customers` → `customer_contacts`：一对多（一个客户多个联系人）
- `work_orders` → `customers`：多对一
- `work_orders` → `customer_contacts`：多对一
- `work_orders.staff_names`：存储售后人员姓名字符串（逗号分隔），通过应用层关联 `after_sales_staff` 表
